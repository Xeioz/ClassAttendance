## Data preservation and export compatibility

The exporter preserves the full selected session, including excused and not-yet-recorded students. Existing attendance-rate denominators are unchanged. Tests compare every attendance field (9), audit field (12) and CSV field (16), exact membership, counts, numerical shares, text types, leading zeros, long identifiers, Unicode, line breaks and formula-like input. Timestamp-zero fixtures ensure that a valid zero is not mistaken for an absent value. No spreadsheet formulas are introduced.

The XLSX layout is explicitly versioned as **schema 2**. Attendance headers move from row 18 to row 1; metadata and totals move to Summary. Existing value-column order is retained with clarified ID headings and appended ID columns. CSV retains its 16 existing columns. See the [complete compatibility contract](export-schema.md). The [sample CSV](samples/attendance-schema2.csv) accompanies the [sample workbook](samples/attendance-schema2.xlsx); use XLSX or text-column CSV import to retain leading zeros in spreadsheet software.

Recovery checks compare all original persisted tables and vault metadata after rejection and prove the original PIN still unlocks. Supported original legacy audit records, optional legacy metadata and legitimate unlisted scans survive restoration. Valid restored history is read and exported. Boundary validation rejects unsupported content before any replacement or usable-backup claim. This evidence is synthetic, not institution-specific recovery certification.

## Corrected coverage language and release gates

Performance was measured; it has no agreed acceptance target. Concurrent import/create behavior was reproduced in the earlier audit; its required policy remains unresolved. Stored workbook metadata and values are verified; desktop rendering and usability are untested. Specified PIN and backup checks passed; broader authorization, privacy and institutional requirements were not assessed by those tests.

**The application is not yet ready for classroom release under its documented gates.** The code fixes and automated export checks are complete, but the following remain open:

- Publish and test the actual HTTPS deployment, final base path, manifest/worker scope and offline assets. Source merge does not perform the manually dispatched deployment.
- Run real camera/decoder workflows and the supported browser/field matrix, including physical-device timing and classroom conditions.
- Confirm cold offline reopening after browser/device restart. The completed Chromium check was an offline tab reload only.
- Export and recover on a second supported physical device. A clean Chromium context is narrower evidence.
- Open the generated workbook in the supported desktop spreadsheet application and check long-text visibility, scrolling, filtering/sorting and absence of repair prompts.
- Obtain institutional privacy, device-handling and retention approval; resolve retirement/concurrency policy before claiming those features meet requirements.

See [deployment gates](deployment.md), [field protocol](field-protocol.md) and the [teacher guide](teacher-guide.md). No physical, deployed-service or institutional check is marked passed merely because local tests or builds succeeded.
