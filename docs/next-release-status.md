# Next-release implementation and verification

Implemented on `feat/teacher-next-release`, starting from `main` commit `3c07af58b62e4c8a6272465826729b3805518c2e`. Verification below was executed on 2026-10-22 with synthetic students. ### Accessibility evidence and limits

Automated axe scans used the WCAG 2 A/AA and 2.1 A/AA tags on workspace creation, templates/readiness, roster review, and the manual-attendance dialog. Each screen had **zero reported violations** on both URL paths. The manual dialog retained an **incomplete `color-contrast` result**; it is not counted as a passed rule. Other scans had no incomplete rules in this run.

Separate keyboard interaction tests cover workspace creation, manual-entry validation/save/cancel and focus return, checklist actions, and switching from closed history to the actual active session. These are automated keyboard exercises, not a human screen-reader study. Screenshot review and width assertions cover a 375 px viewport and 200% root text enlargement; browser page zoom, all translated text expansions, real mobile devices and physical assistive technology remain untested. No WCAG conformance claim is made.

English is the only shipped locale. There are 411 English resource keys at this implementation point, statically bundled for offline use. Unsupported locales/missing keys deliberately fall back to English; an entirely unknown key remains visible as `[key]`. Canonical IDs, statuses, audit actions and spreadsheet schemas are not translated. Low-level platform/crypto exceptions may remain native English. The institution still needs to select additional languages and review translations.

## Data, migration and teacher instructions

[Storage and backup contracts](next-release-storage.md) explain the additive Dexie v2 store, encrypted template payload, backup v2 authentication, v1 compatibility, atomic replacement, and temporary readiness evidence. Restoring a legacy backup deliberately clears templates because the old backup contains none. New v2 backups require this application version; older applications are not promised to open them. Existing session snapshots and export schema 2/CSV values remain unchanged.

The [teacher guide](teacher-guide.md) covers preparation, explicit change approval, stale review recovery, camera/manual alternatives, and template-safe backup/restore. Template/session validation is shared. Entering a start time uses the device timezone; the class/report timezone does not reinterpret that instant.

## Reproducing checks

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm qa:exports
python scripts/verify-qa-exports.py
pnpm build
```

The [browser harness](../scripts/verify-next-release-browser.mjs) needs Playwright and a Chromium executable. It accepts `PLAYWRIGHT_MODULE` (module name or absolute module path), `CHROMIUM_PATH`, `QA_OUTPUT`, `QA_PORT`, `QA_BASE_PATH`, and `QA_DIST`. This environment used `/opt/codex/cua_node/lib/node_modules/playwright/index.mjs` and `/usr/bin/chromium`. The harness starts and stops its own Vite production preview. For a subpath run, build that path into a separate directory and pass matching `QA_BASE_PATH`/`QA_DIST`. axe is pinned as a development dependency. Existing CI automatically discovers the new unit/UI tests and retains the previous build/export checks; no completed remote CI run is claimed here.

## Remaining release requirements

The four feature implementations are complete, subject to the verification limits above. Classroom release still requires the existing [deployment gates](deployment.md): actual HTTPS hosting and worker scope, supported physical browser/camera checks, cold offline launch after browser/device restart, second-device recovery, desktop spreadsheet rendering, and institutional privacy/device/retention decisions. Localhost subpath checks and clean browser contexts do not replace those gates.

The existing approximately 940 KB minified ExcelJS chunk still produces a build-size warning. Export timings are individual synthetic measurements, not acceptance against an agreed performance target. No physical camera decoding, full quota/power-loss test, real student-data validation, or new security certification is claimed.
