Return to Attendance Desk

Browser attendance guide

Open the institution's stable HTTPS website in the browser that holds your records. No application installation is required. Prepare that browser before entering a dead zone. English is the current language.

Students

  1. Check offline readiness while connected, then test reopening without connectivity.
  2. Confirm your official student ID and enter the current room challenge.
  3. Display the QR and wait for the teacher to confirm attendance was saved.
  4. Ask for manual check-in if your device, display or cached website is unavailable.

Review the roster

Unlock local records and choose a CSV with id,name,section headers. Close active sessions before importing. Review all added, updated, unchanged, invalid and conflicting rows. Search, filters and pagination let you inspect the complete file.

For each update, compare existing and proposed names and IDs and approve only if it is the same student. Correct invalid or conflicting rows in the CSV and choose it again. Nothing is saved until the entire file is valid and updates are approved.

Save applies the whole reviewed file, including rows hidden by search. Omitted students remain enrolled. Cancel roster review leaves stored records unchanged. If another tab changes the roster, review the refreshed comparison and approve updates again.

Class templates and preparation

Name and save reusable course, section, room, subject, institution, grace and timezone settings. You can prepare future sections before importing their roster. Choose a saved template to review its settings; update it, duplicate its saved settings, or confirm its removal. Changes to templates leave existing sessions unchanged.

Choosing a template resets the start time to now and clears the room challenge. It does not start attendance or copy a previous roster. Start input uses this device's timezone; the class/report timezone is separate. Check the current roster count and choose a fresh challenge before selecting Create attendance session.

Expand Report details and timezone (optional) to review institution, subject, room, and report timezone. Saved values remain in use when this group is closed. Generate room challenge fills a fresh six-digit challenge; Use current time updates the start draft. Neither action starts attendance.

Pre-class readiness

Complete required class settings, use a saved roster, save or cancel any import review, and close an existing active session. Device and backup recommendations do not prevent manual attendance.

Test camera explicitly requests camera access and releases the camera after the test. Permission, successful camera access and QR decoding are separate facts. A camera failure leaves manual attendance available.

Offline readiness checks cached resources. Test a cold offline launch separately; being online is not enough. Storage estimates can change and persistence can be denied.

Backup evidence shows only activity observed on the current page for this vault. A download request does not prove the file was safely stored. A restore in this browser does not verify recovery on a second device. Unknowns remain unknown, and reloading clears the activity observations.

Record attendance

  1. Verify each student presenting a pass. Start the camera or use Manual check-in / correction (F2).
  2. Wait for saved confirmation. Processing, duplicate, unrecognized and failed outcomes include text. A QR alone does not prove identity.
  3. Manual entries and corrections need a reason. The camera pauses while the dialog is open; Escape cancels when a save is not pending.
  4. For disputed duplicates, hold the review target, verify identity and enter a resolution. Correct attendance separately if needed.
  5. Resolve disputes and review unrecorded students before closing the session to reconcile absences.
  6. Download Excel/CSV and an encrypted backup. Reports include the complete selected session even when on-screen search is filtered.

Reopening and recovery

Closed sessions are read-only. Reopen with a reason to make changes. Automatic closure absences return to unrecorded; explicit teacher decisions remain.

Keep encrypted backups outside this device and check the browser actually saved each file. Lock teacher records to restore a backup with its PIN. Validation precedes replacement of all current local records, including templates. New backups preserve templates; supported older backups restore with no templates and clear current templates.

Test restoration on a separate supported device. Forgotten PINs cannot be reset to decrypt old records. Never clear website data as routine troubleshooting.
